# ASTRIS 2.7 — публічний сайт із Groq AI і постійними щоденниками

Цей проєкт спеціально підготовлений для демонстрації ASTRIS на Render Free. Відвідувачу потрібен тільки HTTPS-адреса/QR-код і демонстраційний акаунт `astra1`–`astra6`. Встановлювати Ollama або запускати комп'ютер автора не потрібно.

## 0. Безпека — зробити перед усім іншим

- Якщо Groq API-ключ опубліковано у чаті, скріншоті або GitHub, негайно **Revoke/Delete** його на https://console.groq.com/keys і створи новий. Старий ключ не використовувати.
- **Ніколи не додавай ключі до коду, README, HTML, ZIP або GitHub.** Вводь їх тільки у Render Environment Variables.
- Публічні астронавтські акаунти призначені тільки для вигаданого екіпажу й синтетичних вимірювань. Реальні персональні медичні дані тут не використовувати.
- Пароль оператора на публічному сайті **обов'язково новий** (не `operatoroperator`) — через `ASTRIS_OPERATOR_PASSWORD`. Пароль повідомляй лише команді.

## 1. Постійне сховище (Supabase Free)

Render Free знищує файли локального диска при перезапуску/засинанні. Тому щоденники та останні результати AI зберігаються в Supabase. Render Postgres Free має обмежений термін 30 днів, тому для довшої демонстрації обираємо Supabase.

1. Зареєструйся на https://supabase.com/dashboard та натисни **New project** → Free.
2. Зайди в **SQL Editor → New query**, скопіюй увесь вміст файлу `supabase-schema.sql`, натисни **Run**.
3. Знайди **Project URL** (у **Project Settings → API** / **Integrations → Data API**). Вигляд: `https://xxxxx.supabase.co`.
4. Зайди в **Project Settings → API Keys** → **Secret keys** та скопіюй серверний `sb_secret_...`.
5. Не використовуй `sb_publishable_...` і не надсилай ключі нікому. На Render вони будуть секретами `SUPABASE_URL` та `SUPABASE_SECRET_KEY`.

Створена таблиця має назву `public.astris_kv` і захищена RLS; доступ до неї має лише сервер із secret key. Клієнтський JavaScript ключа не отримує.

**Примітка:** Free-проєкти Supabase іноді зупиняються після приблизно тижня неактивності — дані не видаляються; проєкт можна відновити в кабінеті. Безкоштовні плани не гарантують безперебійної роботи.

## 2. GitHub — зберігаємо проєкт

1. На https://github.com/new створи репозиторій, наприклад `ASTRIS-NASA`. Для підготовки можна вибрати **Private**.
2. Розпакуй **головний ZIP**. Завантаж на GitHub **вміст** папки, а не ZIP однією річчю: `dist/`, `server.cjs`, `cloud-store.cjs`, `supabase-schema.sql`, `package.json`, `render.yaml`, `scripts/`, `tests/` та документацію.
3. Не завантажуй `.astris-local/`, `.env`, `node_modules/`, API-ключі й власні журнали.
4. У GitHub може бути зручно використовувати Git CLI з PyCharm замість ручного drag & drop.

## 3. Render — публічна адреса

1. Заверши створення Workspace у https://dashboard.render.com/.
2. Натисни **New → Web Service**, підключи свій GitHub та вибери репозиторій `ASTRIS-NASA`.
3. Укажи **Language: Node**, **Plan: Free**, **Build Command: `npm run build`**, **Start Command: `npm start`**, **Health Check Path: `/healthz`**.
4. У **Environment** введи:

| Назва | Значення |
| --- | --- |
| `NODE_ENV` | `production` |
| `HOST` | `0.0.0.0` |
| `ASTRIS_AI_PROVIDER` | `groq` |
| `ASTRIS_GROQ_MODEL` | `qwen/qwen3.8-27b` |
| `ASTRIS_GROQ_DAILY_LIMIT` | `30` |
| `GROQ_API_KEY` | **новий** Groq API Key, тільки в Render |
| `SUPABASE_URL` | URL твого проєкту Supabase |
| `SUPABASE_SECRET_KEY` | серверний секрет `sb_secret_...` |
| `ASTRIS_OPERATOR_PASSWORD` | унікальний секретний пароль оператора (16+ символів) |

`PORT` вводити не потрібно — Render передає його сам. Не вставляй подвійні лапки навколо значень.

5. Натисни **Deploy Web Service**. У логах шукай повідомлення про завантажений Supabase storage і запуск ASTRIS.
6. З'явиться стабільна адреса формату `https://astris-space-health-demo-xxxx.onrender.com`. Вона збережеться при redeploy і перезавантаженнях **поки існує той самий сервіс/домен**. Не видаляй сервіс і не перейменовуй його без потреби.

**Можна також застосувати `render.yaml` як Blueprint:** але в ручному Web Service усі параметри зручніше перевірити перед першим запуском.

## 4. Перевірка перед QR-кодом

1. Перейди на Render URL з мобільного інтернету (не з тієї самої локальної Wi-Fi-мережі).
2. Увійди як `astra6` (пароль `astra6astra6`), перевір **Щоденник** (7 тестових днів), **Моє здоров'я**, **Екіпаж**, **AI-помічник**.
3. В AI натисни **«Отримати персональні поради»**; перевір, що результат має три розділи і вказує модель `qwen/qwen3.8-27b`, метод `groq-ai` (у картці буде назва моделі й токени).
4. Переконайся, що `operator` / `operatoroperator` не працює. Новий операторський пароль працює тільки для команди.
5. Додай до щоденника astra6 тестовий запис і на Render запусти **Manual Deploy → Deploy latest commit**. Увійди знову: запис має залишитися.
6. Після цього згенеруй QR-код командою:

```powershell
python -m pip install "qrcode[pil]"
python scripts/qr-for-url.py https://YOUR-SERVICE.onrender.com
```

У папці проєкту з'явиться `ASTRIS-QR.png`. Цей QR-код не змінюється між перезавантаженнями вебсервісу.

## 5. Якщо щось не працює

- **Deploy fails / Supabase 404/401/403:** перевір SQL-таблицю `astris_kv`, URL, secret key і змінні середовища Render. Сайт навмисно не стартує в production без постійної бази й захищеного operator password, щоб не втратити дані.
- **Groq 401 / 403:** ключ недійсний або відкликаний; згенеруй новий і заміни в Render Environment.
- **Groq 429:** безкоштовні квоти вичерпано; зменш частоту запитів або дочекайся відновлення квот. ASTRIS показує чітко відмічений резервний аналіз, не підміняє його AI.
- **Сайт перший раз завантажується довго:** Render Free засинає після 15 хвилин без трафіку; перший запит може зайняти близько хвилини.
- **Після перезапуску зникли логін-сесії, прогрес місії:** сесії та поточна симуляція в Render Free зберігаються лише в RAM. Слід увійти знову; щоденники та AI-результати зберігаються в Supabase. Для гарантованого збереження прогресу місії потрібне додаткове сховище й окрема логіка відновлення.
- **Supabase Free паузиться після тижня неактивності:** віднови його в dashboard. Під час NASA-показу перевір готовність бази заздалегідь.

## 6. Доступність і квоти

Постійне посилання не означає гарантований 24/7 uptime: Render Free прокидається після запиту, Supabase Free може призупинити неактивний проєкт, а Groq Free має ліміти токенів/запитів. Безкоштовний сайт — **демо для журі**, не production-система. Справжні вимірювання тут не використовуються, а AI не встановлює діагнози.
