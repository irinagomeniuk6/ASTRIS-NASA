# ASTRIS AI: Groq Cloud для журі, Ollama локально

## Головний режим: Groq (Render)

Вебзастосунок підключається до `https://api.groq.com/openai/v1/chat/completions` із сервера Node.js. У браузері тільки результат. Відвідувачам **не потрібні Ollama, Python, GPU чи API-ключ**.

Налаштування Render Environment: `ASTRIS_AI_PROVIDER=groq`, `GROQ_API_KEY=...`, `ASTRIS_GROQ_MODEL=qwen/qwen3.8-27b`. Головний prompt використовує ті самі три розділи: «Що змінилося», «Що спробувати сьогодні», «Що перевірити завтра». У запит входить історія 30 хвилин часу місії, останні вимірювання за 30 секунд, прогнози на 5 хвилин та власний щоденник за 30 календарних днів. Інші профілі не потрапляють у запит.

Безкоштовний тариф Groq має квоти. Ми додали обмеження частоти для демонстрації — 30 сек між запитами одного астронавта та `ASTRIS_GROQ_DAILY_LIMIT` спроб за добу для всього серверного процесу (типово 30). Після перезапуску процесу лічильник скидається, але квоти Groq залишаються. Результат обробки без справжньої AI відповіді позначається як *автоматичний статистичний аналіз ASTRIS*.

**Ніколи не додавайте GROQ_API_KEY до GitHub, файлів проєкту, URL або браузера.** Уже опублікований ключ треба відкликати та замінити.

## Резервний локальний режим: Ollama

Для локального використання без Groq ключа залишається попередня інтеграція з Ollama + `qwen3.5:4b`.

```powershell
ollama pull qwen3.5:4b
$env:ASTRIS_AI_PROVIDER = "ollama"
$env:Path = "D:\Strudy\nodejs;$env:Path"
npm.cmd start
```

У цьому режимі додаток спробує запустити локальну Ollama. На Render Free Ollama 4B не використовується, її ваги в репозиторій не входять.

## Постійне збереження

Продакшн-сервер використовує Supabase REST API. Інструкції в `DEPLOY-GROQ-RENDER.md`. Для локальної розробки без `NODE_ENV=production` старий файловий режим `.astris-local` продовжує працювати.
